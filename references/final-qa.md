# 成片 QA

## 自动门禁

`workflow.py qa` 必须验证：

- 正式渲染前与最终 QA 都运行当前板图 QA；跨区前景、未覆盖前景和无独立锚点均为画面质量提示，不阻断用户确认的制作。未归属前景与某个对象边界内外连续时，报告对象 ID、方向和诊断图，不能只报告像素总数。
- 稀疏且四边连续的整板装饰框从语义前景中排除，不能把本来独立的对象误连成一个跨区笔迹；旧项目已有的长线、箭头和关系线仍按真实前景检查，新图不再生成这些元素。

- 最终文件同时包含视频轨和非静音音轨。
- 音画轨长度差不超过一帧，最低容差 40ms。
- `aspect_ratio` 为 16:9 时，成片宽高必须满足精确 16:9，不能只接受“接近 16:9”。
- `words.json.duration_ms`、最后逐词时间、最后字幕时间和最终音轨尾部必须一致，任何文字或字幕都不能超出声音。
- 每条 SRT 字幕的中点帧在底部安全区存在可见对比像素。
- 字幕正文与锁定原稿一致，每条只有一行且不含标点。默认无空格；仅允许在原稿已有标点边界处，用一个空格分隔同条中的两个完整短句。原稿连续词语内部出现空格属于阻塞错误。独立句意应优先拆开显示；主谓、动宾、虚词边界、强行合并两个句意或过长字幕列为人工编辑警告，不再用固定字数或“语义标点结尾比例”作为硬门禁。
- `audio/tts-script.txt` 必须能由展示原稿和 `audio/pronunciation-overrides.json` 确定性推导；有发音覆盖时必须人工试听实际音频，Whisper 只能提示疑点。
- `final.mp4` 哈希与 `state.json` 一致。
- `overlay-qa.json` 必须通过事件中点可见性和透明背景覆盖检查；工作台预览只作为时间与安全区代理，不冒充最终 WebM 验收。可选事件失败时必须留下明确的 native fallback 记录，必需事件失败时阻断交付。
- 首帧、每幕代表性绘制中点与完成点、换幕衔接、随机 1–2 条字幕和末帧成功抽取；默认视觉抽帧不超过 48 张。其余全量结构与时序检查读取标注、逐词时间和 renderer profile，不为每个事件另存图片。
- 使用 `semantic-v2` 的项目必须为每幕输出 `fast-semantic-trace-v1` 渲染 profile：记录主体组件数、结构锚点、识别/支撑/纹理笔画数、方向分布和 `stage_order`；有细节笔画时，识别笔画与支撑笔画统计之和必须完整对应细节总数。
- 每个对象的 `traced_hand_strokes` 必须等于 `total_strokes`，`deferred_strokes` 必须为 0。允许为了适配真实口播时长统一快速描线，但不允许减少代表性笔画、用一条移动前沿揭示整块图片或在手消失后补完线稿。
- 可见手部仍输出轻量 `hand-motion-qa-v1`，用于发现单帧消失、停住后猛跳等生命周期异常；快速描线本身不再按旧慢速位移阈值判失败。
- `semantic-v2 + local-brush` 必须报告 `object-progressive-v1`。逐对象的实际阶段顺序与帧数须符合 [执行契约](timing-and-recovery.md#三项执行不变量) 和已批准预算；不得用固定比例替代核对。基础色由可见手部逐带呈现，之后才进行可选润色。
- 必须报告当前 `semantic-masks-v1` 像素策略及 `ownership_metrics`，实际执行归属须与批准的对象掩码一致。矩形重叠本身不是错误；疑似缺图、重叠或空选区保留警告；用户接受当前分配后不再拦截。保护区由编译结果排除。旧策略计划须显式重新准备并确认。
- 第三次确认材料必须让用户当前所在界面直接看到整板图、实际绘制预览和存在风险时的诊断图。只有真正展示过的风险才能记录为用户接受；无法访问的本机路径不能代替画面展示。
- V3 视觉抽帧包含每幕一个代表性手绘中段与完成点、一个代表性关键动画的开始/中点/结束、板擦中点和下一幕首词；异常时再围绕最多 5 个事件扩大。
- 新计划每幕后动画为 0 或 1 个，只选择有明确语义与真实时间窗口的 focus-push；无事件合法。不添加轮廓描边高亮、染色或流光。必要撤手至少按共享 180ms 帧预算执行，检查真实相邻帧，不凭静态联系表把突然消失称为误报。
- V3.2 无路径推近和 V3.1 legacy 计划继续按各自旧门禁检查；它们由底层接口兼容读取，但不属于 V3.3 自动生产。

自动报告写入 `deliverables/qa-report.json`，总览写入 `deliverables/qa-frames/contact-sheet.jpg`。自动门禁失败时不得接受成片。
报告版本、报告文件哈希和成片哈希必须与当前验收记录一致；验收规则升级后，旧报告不再维持 `complete`，必须用当前规则重新运行 QA。

## 实际看图

普通视频生产采用轻量抽样：Codex 查看一张不超过 48 帧的 contact sheet、每次换幕的结束帧、随机 1–2 条字幕帧和末帧，不能只读 JSON；只有抽样发现异常或 `hand-motion-qa-v1` 失败时，才围绕最多 5 个最差事件提取相邻帧或扩大范围。不得默认生成或逐张加载全部过程帧。抽样检查：

1. 开场在 0.2 秒内开始有效绘制，不出现无意义长空白。
2. 每次换幕都与新一句旁白同步；擦除和净板合计不超过约 0.5 秒，净板后新幕锚点应迅速出现。真实停顿较长时应保持上一幕完整画面，不能长时间显示空白画布。
3. 抽查代表性元素完成帧，确认未开始元素没有提前泄露，当前元素的头顶、四肢、道具与外轮廓已经完整，不会在后续元素或整幕末尾突然补出；共享、遗漏或被切开的前景计数仅作提示，不要求为零；归属图哈希须与批准的计划一致。
4. 小手或兼容笔尖靠近当前笔迹；手部不得遮挡核心主体。结构、身份、支撑和纹理都应看到对应笔画逐条出现；允许快速，但不能只画开头几笔后由图片自行补齐。
5. 对象按结构与识别、动作支撑、基础色、可选润色推进；基础色跟随可见手部出现。不得让手先消失再整块跳色，也不得用填色扫描替代必要描线。
6. 人物身份、衣着、线条粗细、纸张颜色和强调色跨幕一致。
7. 相邻场景构图不同，不能连续使用横向四图标队列。
8. 字幕单行、无标点、清楚且位置稳定，尽量不覆盖核心画面；自动语义警告逐条人工复核。
9. 末帧显示完整整板图，笔尖消失，至少停留约 0.5 秒。

存在 V3.3 `focus-push` 时只抽查一个代表性事件，发现异常后才扩大检查。它应在 400–650ms 内慢推、停留至少 400ms、幅度不超过 6%、不立即回弹，且不得带出绘图手或变换字幕。自动检查 `phase_budget_metrics` 的原始基线、有效阶段预算与 `actualPhases`；识别和基础色不减少，每个阶段的实际帧数必须与有效预算相等。场景计划哈希应与批准内容一致。人工抽样确认动画结束不晚于本幕最后口播词，音频与场景总时长不变。板擦出现前本幕其他运动停止，字幕保持最终层清楚；非最后一幕擦完后有短暂干净画布，最后一幕不擦除。

全部通过后运行 `accept-qa` 并记录具体观察。不能使用“看起来没问题”等空泛总结；至少说明人物/构图、手部、字幕和末帧四项。

## 失败处理

本节只能修改当前视频项目的输入或产物。视频生产、验收片和回归片不得读取、诊断、修补、同步或备份 Skill、renderer、安装入口和依赖，不得运行代码测试，也不在视频交付中输出源码缺陷或整改建议。现有公开命令无法完成时，将对应生产步骤保留为未完成，等待用户另行发起独立的 Skill 开发任务。

- 只有音画尾长不一致：重新渲染并自动延长最后一幕，不重做图片。
- 字幕缺失或遮挡：保留场景视频，只重新合成。
- 手部遮挡：在工作台把配置改为 `no-hand`，保存并重新确认后重渲染（历史 `bare-tip` 仅是同义兼容别名）。
- 元素提前泄露：修正对应 annotation 的区域或保护区，只重渲染该幕。
- 元素局部到末尾才补出：扩大对应 region 使其完整包围主体，重新运行 `preview`，只重渲染该幕。
- 人物或画风不一致：在已批准风格与分镜不变时，只重生并登记失败整板图，重新准备计划并走第三次画面确认。若需改变风格或语义分镜，则分别回到第一或第二次确认。

## 填色证据

按对象 ID 核对 `color_metrics.object_records`：有待填色像素时检查实际描绘次数与基础色帧数；无待填色像素时不要求虚构填色。全幕总次数不能证明逐对象完成。旧 profile 缺少记录时标记证据不足，不能追认通过；预算政策升级通过显式重建、重新确认处理。细则见 [时间与保存契约](timing-and-recovery.md#基础色记录与预算版本)。帧数下限不替代真实画面的识别速度、笔触连续性与颜色完整性检查。
