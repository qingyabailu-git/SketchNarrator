# 时间窗口与保存契约

## 编辑、生产与确认

工作台是编辑器。任意拖拽、缩放、增删、排序、时间调整、重叠、越界、空框或删除全部框都能保存。保存忠实保留编辑，不夹带几何修正、像素抢占、计划重建或生产检查。生产所需的 1–6 个完整对象等约束只用于准备、预览和渲染，不限制编辑保存。

保存更新当前项目文件并撤销受影响的批准和缓存，保留旧媒体；保存成功仅表示编辑已经持久化。暂时缺少触发短句或语义关联时保留待处理内容。并发版本冲突时保存到 `panel-conflicts/`，明确说明未覆盖磁盘新版本；实际写入失败才报告保存失败。路径、会话和文件类型约束保护项目边界，不是画面质量门禁。

`status.stage` 是当前阶段的唯一来源，`status.next_command` 给出唯一优先动作，`status.allowed_commands` 给出该阶段可以执行的其他公开动作。聊天中的确认先通过相应 `approve` 原子写入状态，后续步骤只读取新状态；不能把“用户已经说过确认”和“项目已经记录确认”当成两个长期并存的事实。

工作台保存与正式渲染的准备、最终提交共用项目写入锁；逐帧渲染期间释放写入锁，用户可继续编辑和保存。渲染提交前在同一锁内重新核对输入与状态，变化则保留用户编辑及旧成片，不把旧状态写回。另设渲染任务锁，防止两个正式渲染同时写同一组缓存。锁只协调使用该协议的公开入口，不承诺拦截外部程序直接改文件；进程退出由操作系统释放锁，不按锁文件是否存在判断占用。

每幕独立撤销和重做，覆盖标注、身份关联、顺序、时间与该幕动画编辑。一次拖拽算一步，保存不清空历史；撤销已保存内容产生待保存编辑，不恢复批准。支持 Ctrl+Z、Ctrl+Shift+Z，文字输入框保留原生撤销。历史随版本绑定保存在浏览器；刷新仅恢复版本匹配的历史，存储不可用时提示，不能承诺跨端恢复。

纯布局或绘制顺序修改撤销第三次确认；语义对象、描述或口播对应关系改变撤销第二、第三次确认，并在保存结果中列出对象总数变化以及新增、删除、修改的稳定 ID。复用原有关卡，不增加第四关。重新确认之前可以继续编辑和保存；真实预览或正式渲染失败不得回滚已经保存的编辑。

## 用户对画面质量的决定权

保存始终允许。第三次确认接受当前计划的画面、对象分配与绘制顺序，包括已展示的像素疑点。布局不完全符合模板、重叠、框外像素和空选区不阻止准备计划或渲染。工作台顺序预览使用计划的 objectMasks；编辑后的框预览只是草稿，应先保存并准备计划，不能把矩形预览称为最终像素效果。

一般疑点只列为提示；明显缺图或对象被切断时最多提醒一次。用户明确认可像素归属或再次要求按现状渲染，就是画面质量的最终决定，代理记录现有关卡确认并执行，不能要求零疑点、重复确认、反复重建或重新生图。禁止合并整幕来消除报告。用户无需填写豁免表或新增确认关卡。

第三次确认绑定用户实际看到的材料。每幕至少直接展示整板图、按批准掩码生成的绘制预览，以及存在风险时的诊断图；风险说明使用对象 ID、对象名称和疑似裁断方向，不用未归属像素总数代替视觉含义。只提供当前设备无法访问的路径，不得记录为已经完成画面检查。

质量判断与执行故障分开：图像无法读取、数据损坏或输入已经改变时如实处理实际原因，不冒充像素质量门禁。批准的像素分配冻结在计划中，渲染和 QA 不重新分配；确认后的内容改变才使该批准失效。

## 三项执行不变量

1. **对象与像素一致。** 语义对象的稳定 `id` 贯穿分镜、标注、计划。移动或排序不改 ID；新增区域创建 ID，不用标签、序号或剩余位置猜测身份。需要分别出现的对象先在分镜和生图阶段保持独立完整。`semantic-masks-v1` 使用源图尺寸的对象掩码表达实际像素归属；每个像素最多属于一个对象，保护区不得被自动补回。无歧义的区域选择可以确定性编译为掩码，重叠像素按较小选区优先、同面积按稳定 ID 分配，调整绘制顺序不改变归属；这只是可见、可修改的选择规则，不声称理解语义。框外像素不自动归给其他对象，以警告说明不会绘制；空选区也仅提示。保护区始终排除。显式掩码优先，计划保存最终独占结果。
2. **批准与执行同版。** 唯一 `animation-plan.json` 保存 `objectMasks`、`drawingBudgets`、`renderSettings` 和输入指纹。第三次确认绑定内容哈希与输入指纹。预览读取保存版本，正式渲染读取批准版本，使用按内容哈希命名的执行副本。编辑使旧计划过期；工作台“准备执行计划”按钮或显式 `rebuild-plan` 才重新准备，先保留旧计划备份，不在保存或渲染入口偷偷修复。准备不代表用户批准。掩码对象使用 `size: [width, height]` 与 `runs: [[y, xStart, xEndExclusive], ...]`，可选标注 `pixelMask` 提供明确的源图选区；未提供时按上述固定规则编译区域选择。背景纹理或杂点确认为非对象内容后，可用同格式 `backgroundMask` 明确排除；不能自动吞掉邻近对象。安全框适配统一变换图片、区域、保护区和掩码。
3. **保护预算落实到帧。** 时间计划来自真实音频；每个目标帧率由同一编译器确定性量化。正式输出预算保存在计划中，预览按自己的帧率编译而不改正式基线。顺序统一为结构与识别线条、动作支撑、基础色、可选润色；识别和基础色不得为后动画缩短。时间不足先取消可选效果，仍不足则明确指出冲突。工作台、renderer 和 QA 对照同一预算与实际阶段帧数，不能只看总时长相等。

## 旧项目迁移

`migrate-project --project <项目目录>` 显式补全可无歧义恢复的身份字段，保存到 `migration-backups/` 并生成 `migration-report.json`，撤销受影响批准。缺少触发依据或无法确定身份时列为待处理，不按字数或序号补时间，不自动追认旧计划。迁移不生成配音、板图或成片。完成上游复核后，再显式准备计划并重新确认。

## 同一音频时钟，三种用途

- `storyboard.scenes[].start_ms/end_ms` 和项目内相同字段表示本幕口播边界，必须保持一致。
- `annotation.sceneDurationMs` 表示口播内的绘制时间预算，不能为转场延长。
- 动画计划保留 `sceneStartMs/sceneEndMs/sceneDurationMs` 的口播含义，另记 `narrationEndMs` 与 `renderEndMs`。非末幕的渲染结束为下一幕开始；最终输出还包含真实音频尾部。

幕间停顿归上一幕渲染，完整画面保持和板擦都发生在这段停顿内。首幕之前的实际静音才使用 lead frames。正式渲染、单幕真实预览和工作台播放均覆盖这段停顿；编辑元素绘制时间时仍使用口播预算。不能通过延长 storyboard、修改目标时长或压缩配音解决转场报错。

## 参考视频的实际观看记录

完整参考分析对压缩视频只做一次顺序解码，以最高 4Hz、最多 4800 个样本检测运动与镜头，禁止对每个样本反复随机寻址。关键帧优先抽取开头 0、1、2、3 秒，然后把其余名额分配到全片时间位置和镜头中部。联系表受抽样数量限制，不代表已经看完视频。`low-frame-difference` 不能解释为静止镜头；使用分析包中的本地视频路径和 `suggested_motion_windows` 检查连续变化，并补看长镜头中段和末段。

Codex 实际观看后生成如下 JSON，再调用公开入口登记。示例时间和文字必须替换为当前素材的真实观察；登记只检查材料结构和来源绑定，不能替代实际观看。

```json
{
  "opening_hook": "开场画面如何提出问题",
  "visual_style": "人物、线条、配色、构图观察",
  "subtitle_style": "字幕位置、切换与强调观察",
  "pacing": "镜头时长、画内变化和停顿观察",
  "adaptation": "原创视频如何迁移这些表达，以及哪些不沿用",
  "motion_windows": [
    {"start_ms": 0, "end_ms": 3000, "observation": "实际看到的连续动作"}
  ]
}
```

```powershell
scripts\run.cmd review-source --project <项目目录> --review <观看记录.json>
```

观看记录写入当前项目 `source/visual-review.json`，并绑定分析清单哈希。重新提取参考素材后需要重新登记。原来的机器分析清单保持原样，不能直接把空白占位项改成“已分析”。分镜中说明参考的镜头规律如何转换为当前主题的画面；不要照搬原视频时间轴。

## 语义触发与标注

分镜每个元素提供唯一 `id`、`label` 和 `trigger_text`，其中 `trigger_text` 是本幕真实口播中的连续短句。匹配跨越 words.json 的多个词；重复出现而无法唯一定位时，使用 `visual_beats` 的 `trigger_word_id` 与 `target` 指定真实词和元素。不再按元素数量平分词序，也不在长镜头中点自动添加强调。长镜头需要有依据的内部节拍，缺失时补充分镜再登记声音与视觉计划。

新分镜在 `stage-script-voice` 内统一编译。编译器可以补齐未批准草稿中可安全确定的场景 ID、对象 ID、兼容字段别名和缺省构图；不得凭元素数量猜测触发时间。验证必须汇总全部独立问题一次返回，再生成并保存正式 `storyboard.json`，不能依赖多次失败逐项发现契约。

```powershell
scripts\run.cmd annotation-template --project <项目目录> --scene-id <场景ID> --image <整板原图>
```

该命令读取实际图片尺寸，生成 `annotations/<场景ID>.draft.json`，不会覆盖旧草稿。Codex 必须实际看图，填写每个 `region`、`reveal` 和触发短句，完成后将 `status` 改为 `ready` 再使用 `add-board`。空区域不会自动成为全画布区域。

标注元素 ID 必须逐一对应分镜元素 ID；可选 `sourceElementIds` 只能包含当前同名 ID。不可分割的对象在分镜中先定义为一个单元。无显式 ID 的旧分镜通过显式迁移生成稳定标识，标注对应关系必须无歧义。工作台展示来源和分组说明，但允许用户增删区域；生产层自动协调身份与分镜同步，用户不被要求修改分镜。

原图尺寸必须与标注 canvas 完全一致。安全框缩放在此检查之后统一变换图片和坐标。不得先按猜测的高清画布标注，再把低分辨率图片拉伸以通过登记。

## 工作台保存与恢复

启动时 `PANEL_PLAN_READY` 报告已保存计划是否仍有效。失败时编辑器仍可打开用于修正；不能把“页面已打开”报告为“可以渲染”。保存的 dry-run 和正式应用只检查写入边界与版本冲突，不执行对象、像素或动画质量检查。仅修改标注时保留旧计划并标为过期，不偷偷重建。写入异常按本次事务备份恢复。

工作台将未应用变更保存在当前浏览器来源的本机存储中；刷新同一工作台时，仅在项目指纹和原文件哈希一致时恢复。磁盘内容变化时保留旧草稿但不覆盖。浏览器清理存储、更换端口或隐私模式可能使草稿不可用；存储失败时页面会提示不要关闭，也可以使用原有导出变更集功能保存当前修改。草稿不代表已应用，保存不代表成片验收。

只有派生动画计划需要重建、上游登记仍有效时：

```powershell
scripts\run.cmd rebuild-plan --project <项目目录>
```

该命令检查上游登记和分镜一致性，重建动画计划并使第三次确认、旧渲染缓存、成片状态与 QA 失效；保留原稿、声音、板图和标注文件。若上游已经改变，应先使用对应公开入口登记变化层，不能补写 state 哈希绕过。

## 成片输入凭据

正式渲染记录实际生产文件哈希，并检查渲染前后是否一致。变化时临时成片不能替换原 final。成功后 `deliverables/render-receipt.json` 保存输入快照、渲染器指纹、选项和 final 哈希；替换旧片时一并归档旧凭据。

字体、音频、外部片段与音效清单在场景渲染前完成预检。显式 `--no-sfx` 不读取外部音效配置；外部设置没有 `sfx` 字段时使用项目和公开包默认值，不把它解释成损坏。每幕成功后立即把缓存键、文件哈希和输入摘要写入 `renders/scene-cache.json`；即使合成、音效或字幕阶段失败，下一次执行仍先核对并复用这些场景。`state.json.render_cache` 保存最近一次完整流水线采用的同一批记录，两者都必须经过内容哈希核对，不能仅凭文件存在命中。

`qa`、`accept-qa`、项目校验和完成状态都要求当前生产文件与凭据一致。历史成片如果没有凭据，不能追认其当前有效性；后续经用户授权重新渲染时才生成凭据。文件匹配仅证明输入对应关系，仍需实际查看媒体完成最终验收。

### 基础色记录与预算版本

`protected-phases-v2` 在原始预算中给基础色至少 8 帧，使三次描绘及换行具有实际帧空间；不足时在准备计划阶段报告冲突，不在执行时缩减次数。该帧数是执行下限，不代表所有尺寸和时长的视觉效果已经通过。纯线稿对象记录零待填色像素和零填色次数，不伪造上色。QA 按稳定对象 ID 检查 `color_metrics.object_records`，不能用其他对象的次数补足。旧计划不会自动升级；需显式重建并重新确认，旧总量记录只能标为证据不足。

## 登记、检查与计划准备

单幕 add-board 登记不触发全片动画编排。登记后输出本幕像素归属结果与问题图；未解决也保留当前编辑并允许工作台保存。check-boards 一次列出每幕错误，rebuild-plan 在编排前汇总全部归属问题。错误必须带场景 ID 和诊断文件，不得把登记命令的场景误当成所有上游错误来源。semantic_sync_pending 由显式准备同步，不通过反复迁移或复制项目消除。

`protected-phases-v3` 保留必要撤手帧（共享 180ms，至少两帧），它不是可删除的润色；可选效果只能使用多余收尾与纹理。识别完成比例按原始预算计算，避免可选效果缩短分母制造验收失败。旧计划需显式准备并重新确认，不静默升级。局部轮廓、染色高亮和流光只保留历史播放代码，新计划和工作台不再提供这些效果。
