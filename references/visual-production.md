# 视觉制作规范

## 风格与角色锁

先从 [风格注册表](style-registry.json) 读取当前 `style_id` 的背景、线条、色板、填色、纹理、构图、参考图和禁用项。一个项目只使用一个风格配置；不得在不同场景临时改色板或线条语言。当前十种注册风格共用现有视觉导演与渲染器，不另建第二套路由系统。`orderly-color-doodle` 用于需要亲和力的开源、工具和轻科技讲解：保留毡尖笔的一笔轮廓、轻微压感变化、个性化人物比例和少量动作线；颜色采用干净、不透明、无排线和无渐变的直接平涂。规整只约束阅读路径、宽松基线、对象间距和字幕留白，不把画面做成机械对称的矢量图标阵列。

重复人物先建立角色参考图，并在 `storyboard.json` 的 `characters` 中登记稳定 `id`。每幕生图都传入同一参考，保持发型、脸型、衣着、主色和年龄一致。没有重复人物时不要额外生成角色表。

手部覆盖默认使用 `small-hand`：最终输出画面短边的 12%–16%，推荐 14%。默认 `fast-semantic-trace-v1` 不再追求慢速匀滑运动，而是在元素的真实时段内按语义顺序快速描完全部骨架笔画；跨笔画连接处必须抬笔且不能落出假线。允许快速，不允许开头慢画几笔后突然扫描补图，也不允许手消失后补完线稿。结构与识别、动作支撑完成后，手部执行 `serpentine-flat-fill-v1` 呈现基础色，再绘制可选纹理与润色；阶段帧数使用已编译计划。自有 IP 使用通用 `presenter`，读取 `renderer/assets/presenter.json` 或 `SKETCHNARRATOR_PRESENTER_MANIFEST` 指向资产包的身份锁、尺寸、笔尖和板擦锚点；禁止镜像等角色约束由资产包声明。角色不足其 `minimum_visible_ratio` 时整层隐藏，真实笔迹或擦除仍继续。`no-hand` 完全关闭手部，`full-hand` 只用于兼容旧项目。历史 `bare-tip` 是关闭覆盖的兼容别名。

## 构图选择

在整板图之前先读取 `visual-plan.json`。它把每个 section 映射为连续 shot，再把 shot 内的绘制、揭示和强调映射为 beat。每个 shot 的 `layout_plan` 是生图前置契约：`native_regions` 决定手绘对象可占用的位置，`caption_region` 固定底部字幕区。两者在同一个画面中共同设计。`shot_type` 只描述表现路径：`a_host`、`a_reaction`、`b_whiteboard`、`b_infographic`、`b_screenshot`、`b_text`。A-roll 只保留 `actor_slot`、`emotion`、`action` 等逻辑槽位；没有 presenter 素材时按 plan 中的 fallback 降级，不临时生成或修改 IP 资产。

第一版模板为 `question`、`focus`、`three-items`、`comparison`、`cause`、`process`、`timeline`、`summary`。模板负责语义组织，`composition` 负责空间组织，两者都要服务于口播目的。截图或录屏缺失时，沿用 `required_assets` 或明确 fallback，不画假界面。

所有 shot/beat 的时间必须来自锁定后的 `audio/words.json`。普通 shot 低于约 2 秒必须有短内容例外；超过约 12–15 秒必须有内部真实 beat；连续三个 shot 不得完全复用模板和构图；同一时间最多两个运动主体。visual beat 进入 `animation-plan.json` 时同时携带语义目的、开始状态、结束状态、静止锚点、候选效果和稳定降级。V3.3 再检查真实前景像素与 900–1200ms 自然窗口，任一不满足就不安排强调。

每幕选择一种构图，并让构图服务于语义：

| composition | 适用关系 | 画面组织 |
|---|---|---|
| `causal-chain` | 原因导致结果 | 起点、变化、结果形成清晰路径 |
| `before-after` | 错误与正确、前后变化 | 左右或上下对照，中间保留分隔 |
| `center-spoke` | 一个核心连接多个因素 | 主体居中，因素分布四周 |
| `timeline` | 步骤、阶段、时间推进 | 沿折线或弧线排列节点，避免纯图标横排 |
| `vertical-layers` | 上下游、输入处理输出 | 分成上下三层，用位置和尺度形成阅读顺序 |
| `character-action` | 人物行动引发后果 | 人物为主，动作、对象和结果围绕人物组织 |

相邻场景避免重复同一构图。新图不生成箭头、关系线、分隔线和可见网格；用位置、大小、动作和留白表达关系。不得因模板名含因果、步骤或对比而补线。

## 整板图硬约束

- 16:9，一幕一张完整整板图，按真实语义包含 1–6 个绘制元素，不为凑数量拆分或合并。
- 一个完整人物、道具及其不可分割的识别细节通常属于同一元素；只有能够独立隐藏、独立出现且不会裁断相邻对象时才拆开。新图不增加连接线、箭头或分隔线，依靠位置与留白表达关系。
- 生图前按 [可独立绘制单元](unified-visual-language.md#可独立绘制单元) 为需要分别出现的元素安排独立空间和净空。每个单元保有完整轮廓、动作和道具，不共用前景笔迹；不能让一个大框笼统覆盖多个先后出现的对象。整板图完成后先检查各单元能否独立显示和隐藏，再制作标注。
- 底部约 14% 完全留给字幕，顶部和左右各保留约 4% 构图余量。所有主体先在完整 16:9 画布中等比缩小并居中到安全框，不得靠整体上移来腾字幕区，也不得裁掉头顶、四肢或道具。
- 整板图只能在 `layout_plan.native_regions` 内组织主体，并始终保持 `caption_region` 干净。
- 禁止文字、字母、数字、Logo、水印和装饰边框。精确中文由本地字体叠加。
- 禁止摄影、复杂 3D、厚重光效和大面积渐变；这些内容不能稳定转成笔迹。
- 开场锚点应足够大，新幕开始 0.2 秒内出现有效笔迹，避免大面积空白配一小段线。

## 提示词结构

每次生成必须明确：

1. 这一幕唯一解释的语义步骤。
2. 1–6 个按语义自适应的元素及其动作、表情和关系，并说明为什么需要拆开或合并。
3. 本幕 `composition` 的空间组织方式，以及 `layout_plan` 中手绘区和字幕区的归一化坐标；明确说明每个手绘对象属于哪个 `native_region`，并要求任何线条、填色、纹理或道具都不得进入字幕区。
4. 风格注册表中的背景、线条、色板、填色、纹理、构图和禁用项。
5. 同一风格唯一的 `reference_image`；它同时用于生图参考、工作台卡片和阶段验收，不复制第二份资产。
6. 可选角色参考与必须保持的身份特征。
7. 四周安全框、底部字幕区和无文字等硬约束；新图不生成箭头、虚线轨迹、指向线、分隔线或可见网格；明确写“整体略小、完整露出、禁止裁切”，不要只写“主体上移”。

拼接顺序固定为“本幕语义与元素 → 本幕构图与角色参考 → 风格参考图与风格契约 → 安全框及禁用项”。不依赖模型猜测风格名称，也不把参考图当成需要复制的具体画面。

不要固定写“从左到右四个区域”。同一视频的相邻场景应使用不同构图，但颜色、人物和线条保持一致。

## 标注与节奏

先听对应口播，再查看原图，最后标注。顺序由叙事决定，坐标由像素决定。

- 先画语义锚点，再画动作或变化，最后画结果。
- 区域必须完整包住可见主体，并在头顶、四肢、外轮廓和道具边缘保留约 16–24 像素笔触余量；不要为了避开邻区而裁掉主体的一部分。
- 同一个人物或道具不得跨越未登记区域。若一个完整主体需要分两段绘制，应拆成明确的语义元素；不能依赖整幕最后强制显示原图来补齐漏画部分。
对象掩码记录实际绘制内容。布局和像素疑点用于提示，不是用户确认后的否决条件；确定性选区分配、确认与执行规则见 [执行契约](timing-and-recovery.md#三项执行不变量)。
- `board-qa.json` 必须检查真实前景重叠，而不只计算矩形相交面积。元素没有独立前景锚点时，先回到分镜判断它是否本就不可分；是否调整由实际效果和用户决定，不因缺少独立锚点强制重排或重画。不得仅为通过 QA 合并需要分别出现的单元，也不得依赖绘制顺序碰运气。
- 一条面积明显的连续前景笔迹跨越多个元素时保留 `split_foreground_components` 诊断；生产层已经按唯一归属绘制，不要求用户为了通过保存手工切断箭头、人物或气泡。
- 绘制时长按骨架路径长度和对应口播时段分配，不按矩形面积平均分配。
- 新项目按已确认对象掩码逐对象完成结构与识别、动作支撑、基础色和可选润色；必要笔画必须真实描出，不用整块图片补完。
- 笔速按路径曲率变化：较长直线快速通过，转折、短细节和换笔处减速；不得把所有笔迹做成同一速度的扫描。
- 各阶段以计划中的整数帧预算为准，基础色在结构与识别完成后由可见手部逐带填入，之后描绘可选纹理。不得重新按比例缩短已保护阶段或在整幕末帧统一补图。
- 短视频建议每 1.5–3.5 秒出现一次有效视觉变化；平缓长讲解可放宽到 3–5 秒。
- 每幕结束至少保留约 0.5 秒完整画面。

`workflow.py add-board` 会在需要时执行等比安全框适配，并同步缩放 annotation region。运行 `workflow.py preview` 后查看 `board-qa.json` 和全部编号预览。`uncovered_foreground_ratio` 只提供定位依据；系统还会指出疑似被区域边界裁断的对象和方向。源图中的明显笔迹最好落入对应 region，但这些画面质量信息只进入第三次确认提醒，用户确认渲染后不再阻断。自动检查不能判断人物是否真的是同一个人，角色连续性仍需实际看图。

## 轻量动画导演

新动画计划以逐对象绘制和稳定停留为主，不生成轮廓提示、局部染色高亮或流光；只在明确聚焦意图与足够时间时使用 focus-push。基础色、识别与必要撤手受到保护，准备后展示并批准，不在渲染时重建。

默认配方不随构图自动补线：

| composition | 默认行为 |
|---|---|
| 任意构图 | 按批准顺序逐对象完成人物和道具，不添加连接线 |
| 真实箭头、路径、关系像素 | 保持稳定，不添加局部高亮 |
| 警示或风险对象 | 保持稳定，不添加局部高亮 |
| 明确结论对象 | 保持稳定，不添加局部高亮 |
| 明确聚焦对象 | 真实窗口 >=1200ms 时可做一次 `focus-push` |
| 任意构图 | 没有可靠结论或窗口不足时记录 `skipped`，不生成强调事件 |

每幕最多一个语义效果，每个事件必须有高置信度前景 `focusTarget`，不得带 `gesturePath`/`path`，不得制造框、圆、横线或箭头。局部轮廓、染色高亮与流光不进入新计划；聚焦慢推 400–650ms、停留至少 400ms、幅度 4%–6%，默认不回弹，字幕不参与变换。动画必须在口播仍继续时完成，不占用幕间气口。V3.2 与 V3.1 效果仅作旧计划兼容或显式实验。板擦出现前停止本幕其他动画；若语义、像素目标或时间不足，只能跳过并记录原因。

非最后一幕按真实逐词时间计算转场：停顿较长时先保持完整画面；只在下一句前最后约 500ms 内完成“横向往返擦除 240–420ms → 净板至少 60ms”。擦除与净板合计不得超过 500ms，不人为追加停顿。字幕在最终合成层叠加，不进入板擦掩码。最后一幕不擦除，收手后保留完整画面。

局部像素后动画已退出新计划；focus-push 需要独占安静窗口，不能与后续对象绘制并行。
